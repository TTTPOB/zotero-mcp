# ADR 0008：精简读取摘要并补充发现上下文

- 状态：已采纳
- 决策者：人类（2026-11-11 在评审中逐项选定）
- 日期：2026-11-11
- 涉及：A1、A4、A5、A6；读取投影、搜索父条目与集合列表

## 背景

旧摘要把相同 key 重复放进全文入口，输出恒为 `unknown` 的索引状态及恒为 false 的命中详情标记，并用 null 或空字符串填充缺失字段。附件或笔记命中只给父 key，模型还需额外调用才能知道属于哪篇论文。集合原生对象包含 `library`、`links` 和重复的 key/version。

父文献的最佳附件实际位于 `links.attachment.href`。Zotero 的 `links.enclosure` 属于导入型附件的本地文件链接，不能用来判断父文献的最佳附件。真实 Zotero 10.0.6 验证了这一差异。

## 决定

1. 用一个函数从父文献 `links.attachment.href` 提取最佳附件 key，摘要和全文选择共用。只有它确实属于该文献的子附件候选时才优先使用；没有首选时仍按唯一附件、唯一 PDF、歧义错误处理，不逐个试读。
2. 摘要始终保留 `key`、`version`、`item_type`、`title`。可选的年份、作者、DOI、父 key、命中附件 key 和候选附件 key 缺失时省略。删除重复全文入口及固定状态，顶层提供 `candidate_attachment_key`；`key` 就是全文工具接受的 `item_key`。
3. 搜索摘要中的子命中增加 `parent`，含父条目的标题、作者摘要和年份，缺失字段省略。当前页父 key 统一批量请求，父标签筛选共用同一批数据；没有子命中时不请求父条目。搜索分页仍使用原搜索页的响应头，不用父读取覆盖。
4. 各列表的笔记摘要标题使用去除 HTML 后的第一个非空行，最多 120 字符。普通条目保留完整标题。
5. `get_collections` 默认返回 `key`、`version`、`name`、`item_count`，子集合另有 `parent_key`；`view="raw"` 保留原生对象。`item_count` 使用 `meta.numItems`。真实种子库中，一个含论文及其 PDF、笔记的集合返回 1，空子集合返回 0。

## 理由

保留下一步操作真正需要的信息，减少无值字段与重复 key。父条目标题直接解决子命中无法辨认所属论文的问题，按页批量读取避免逐命中请求。原生视图仍能获取完整信息，不需要兼容旧摘要的重复字段或引入新缓存。

## 考虑过的选项

- 保留 `fulltext` 对象和未知状态：没有额外信息价值，不采用。
- 继续解析父条目的 `links.enclosure`：与真实 Zotero 数据不符，不采用。
- 把子命中替换成父文献：改变命中语义、数量与分页，不采用。
- 每个子命中单独请求父文献：相同父 key 会重复请求，不采用。
- 集合默认保留原生对象：浏览只需少数字段，原生结构改由显式 raw 获取。

## 重新评估的触发条件

- Zotero 改变最佳附件链接或集合计数语义。
- 实际使用发现当前页父上下文仍无法识别所属文献，例如批注需要跨附件再到论文的上下文。
- 新任务确实需要额外摘要字段，且不能由 metadata/raw 满足。
