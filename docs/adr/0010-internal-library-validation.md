# ADR 0010：内部 Library 校验边界与兼容层清理

- 状态：已采纳
- 决策者：人类（2026-11-11 在评审中选定 B1、B2）
- 日期：2026-11-11
- 涉及：内部 Library 参数校验、错误类、写入结果类型与全文错误码

## 背景

这是个人单用户使用的本地 Zotero MCP 工具。`Library` 是服务器内部实现，不是受支持的 Python API；当前没有脚本调用者需要它提供独立的参数校验或兼容层。

MCP 参数已经通过 Pydantic 根据类型、`Field` 约束和 `Literal` 校验。方法内部再次检查相同的类型、范围、长度或枚举，不会处理额外的 MCP 输入。直接以无效 Python 参数调用 `Library` 的测试只验证这套重复规则，不能证明 MCP 边界的行为。

错误类还保留了 `ValueError` / `RuntimeError` 双继承、没有独立行为的全文错误子类，以及没有当前消费者的写入结果别名和按消息文本匹配的 `NO_INDEX` 错误码。这些兼容层增加维护面，却没有对应的实际需求。

## 决定

1. **Library 是内部类。** 类型、范围、长度和枚举约束仅由 MCP 参数 schema 执行，删除方法内部已被 schema 覆盖的重复校验。不承诺直接 Python 调用传入无效参数时的行为。
2. **保留真实业务规则与规范化。** schema 没有表达的跨字段规则、去空白后的非空要求、动态 Zotero 类型、受保护写入字段和实际附件内容限制继续由实现处理。key 大写转换、分页参数构造等规范化保留。
3. **移除四项兼容层。** `LibraryError` 直接继承 `Exception`；删除 `FulltextError` 空子类，统一使用 `LibraryError`；删除 `WriteResponse` 别名，使用 `WriteResult`；删除没有生产者的 `NO_INDEX` 常量、构造函数与按消息文本识别的分支。全文错误继续使用有实际生产者的具体错误码。
4. **不改变 MCP 契约。** 清理前后通过内存 MCP 会话比较工具名、说明、输入 schema 和输出 schema。测试应通过 MCP 验证参数拒绝，通过结果或线上请求验证行为，而不是为删除的内部校验保留直接调用测试。

## 理由

一个真实边界只维护一份静态参数规则，避免重复实现与测试产生虚假的兼容承诺。保留业务规则和规范化，不把 Zotero 的动态行为误当作静态 schema 能处理的问题。没有消费者的继承关系、别名和错误码直接删除，不用兼容包装替代。

## 考虑过的选项

- **保留内部重复校验以支持任意脚本：不采用。** 目前没有受支持的脚本消费者；这会为假设需求维护第二套规则。
- **删除全部校验：不采用。** 跨字段要求、空白内容与动态数据规则并未被 MCP schema 覆盖，仍有实际用途。
- **保留旧类和类型名作为兼容别名：不采用。** 只延续没有消费者的维护负担。
- **继续按错误消息识别 `NO_INDEX`：不采用。** 当前代码没有产生该消息的路径；真实全文路径已经提供具体错误码。

## 重新评估的触发条件

- 有人确实需要从脚本导入 `Library`，并要求受支持的 Python API；届时先明确支持范围与入口，再决定校验位置。
- MCP 框架不再执行现有参数 schema，或实际输入证明某个必要约束未在入口生效。
- 新的 Zotero API 路径产生现有具体错误码无法表达的索引状态；先记录真实响应和调用需求，再决定是否增加错误码。
